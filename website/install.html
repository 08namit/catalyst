Installation

Install Catalyst

Install from source. Catalyst v0.1 is in development and is not published to npm. Every command below runs from a clone of the repository.

Looking for the v0.2 agents preview? It is a separate, unmerged branch with additional setup steps.

1. Prerequisites (both laptops)

  • Node.js ≥ 22.13
  • git
  • Claude Code (the claude command)
  • Both laptops on the same LAN or VPN, able to reach each other over TCP

2. Install from source (both laptops)

git clone https://github.com/08namit/catalyst.git catalyst
cd catalyst
npm install
npm run build
npm link            # puts `catalyst` on your PATH
catalyst --version

Remove the command later with npm unlink -g catalyst-coord.

3. Pair a project

Each developer works in their own clone of the project, not of Catalyst. Each checkout counts as one participant.

Developer A

cd ~/code/your-project
catalyst init --name "Tiam"
catalyst pair

init creates .catalyst/ (gitignored), installs the Claude Code integration and starts the daemon. pair prints a single-use invitation valid for 15 minutes. If the advertised address is wrong, use catalyst pair --host <ip>.

git add .mcp.json .claude/settings.json CLAUDE.md .gitignore
git commit -m "Add Catalyst"

Developer B

cd ~/code/your-project
catalyst join cat1_… --name "Namit"

Send the cat1_… token over a private channel. Then run catalyst status on both laptops and compare the 8-character confirmation code. If it differs, stop.

4. Use it from Claude Code

claude

Start Claude Code in the project on both laptops. In an interactive session, approve the catalyst MCP server when prompted. The first SessionStart briefing appears automatically.

5. Check the connection

catalyst status       # peer state, pending deliveries, sessions, conflicts
catalyst doctor       # installation, permissions, daemon health, Claude setup
catalyst dashboard    # opens the local dashboard (optional)

6. Try an outage

catalyst peer pause
catalyst peer resume

Pausing stops peer networking only. Both sessions keep working and new events are saved locally and queued. On resume, missed events replay and catalyst status shows the queue draining.

Network and trust

Network

Allow inbound TCP on the peer port shown by catalyst status, and allow node if macOS asks. There is no NAT traversal and no relay. The local API and dashboard listen on 127.0.0.1 only.

Trust

An invitation is a bearer secret for 15 minutes and single-use. The peer link is TLS 1.2 PSK with forward secrecy. Every event is Ed25519-signed. Peer content reaches agents as quoted data, never as instructions.

Separate branch · Preview

v0.2: named agents and a shared task queue

This preview adds named Claude subagents, a shared queue, and setup through Claude. It is not merged into v0.1 or published as a remote install. Each developer needs the local v0.2-agents branch available in their Catalyst checkout. From that Catalyst checkout, create a separate worktree to try the preview without merging it:

git worktree add ../catalyst-preview v0.2-agents
cd ../catalyst-preview
npm install
npm link
catalyst install

npm link switches the global catalyst command to this preview checkout. Use a fresh test project. Repeat on the other developer’s machine, where that branch must also be available locally. Do not merge the branch to try the preview.

Connect and try the preview

  1. In the project, open Claude Code and say: “Set up Catalyst and invite my teammate.” Send the cat1_… invitation privately to your teammate.
  2. Your teammate says: “Join Catalyst with cat1_…”. Compare the confirmation codes and restart Claude Code on both laptops so hooks load.
  3. Ask Claude to plan work as Catalyst tasks, publish the decisions the agents need, then use subagents to work through the shared queue. Run catalyst for a brief status.

Preview status and compatibility

v0.2 uses protocol v2 and cannot sync with v0.1 project data. Create a fresh Catalyst project and pair again. The headless two-node, multiagent run is documented; interactive setup and physical two-laptop multiagent validation are still pending. Treat this as a preview and expect to recreate preview projects when returning to v0.1.

Known gaps: the lead cannot rename itself with set_agent_name, and hook activity captured while the daemon is down is imported as the lead’s activity.

Uninstall

catalyst uninstall claude   # removes only Catalyst's entries from .mcp.json, .claude/settings.json, CLAUDE.md
catalyst stop
rm -rf .catalyst            # deletes this project's local event log, identity and keys. Cannot be undone.
npm unlink -g catalyst-coord

Catalyst shares context, not source files. Keep using Git to integrate code.
