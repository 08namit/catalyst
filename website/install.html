Install Catalyst

Install from source. Catalyst v0.2 with agent coordination and recovery is available on main. It is not published to npm. Every command below runs from a clone of the repository.

Read about checkpoints, handoffs and v0.1 compatibility. Interactive two-laptop validation remains pending.

Installation steps

  1. Prerequisites (both laptops)

    • Node.js ≥ 22.13
    • git
    • Claude Code (the claude command)
    • Both laptops on the same LAN or VPN, able to reach each other over TCP

  2. Install from source (both laptops)

    git clone --branch main https://github.com/08namit/catalyst.git catalyst
cd catalyst
npm install
npm run build
npm link            # puts `catalyst` on your PATH
catalyst --version
catalyst install

    Remove the command later with npm unlink -g catalyst-coord.

  3. Pair a project

    Each developer works in their own clone of the project, not of Catalyst. Each checkout counts as one participant. After installation, you can ask Claude “set up Catalyst and invite my teammate”; your teammate asks “join Catalyst with cat1_…”. The terminal equivalent is below.

    Developer A

    cd ~/code/your-project
catalyst init --name "Tiam"
catalyst pair

    init creates .catalyst/ (gitignored), installs the Claude Code integration and starts the daemon. pair prints a single-use invitation valid for 15 minutes. If the advertised address is wrong, use catalyst pair --host <ip>.

    git add .mcp.json .claude/settings.json CLAUDE.md .gitignore
git commit -m "Add Catalyst"

    Developer B

    cd ~/code/your-project
catalyst join cat1_… --name "Namit"

    Send the cat1_… token over a private channel. Then run catalyst status on both laptops and compare the 8-character confirmation code. If it differs, stop.

  4. Use it from Claude Code

    claude

    Start Claude Code in the project on both laptops. In an interactive session, approve the catalyst MCP server when prompted. Restart Claude Code once after project setup so the hooks load. The SessionStart hook provides a briefing. Commit the integration files and keep .catalyst/ out of Git.

  5. Check the connection

    catalyst status       # peer state, pending deliveries, sessions, conflicts
catalyst doctor       # installation, permissions, daemon health, Claude setup
catalyst dashboard    # opens the local dashboard (optional)

  6. Try an outage

    catalyst peer pause
catalyst peer resume

    Pausing stops peer networking only. Both sessions keep working and new events are saved locally and queued. On resume, missed events replay and catalyst status shows the queue draining.

Network and trust

Network

Allow inbound TCP on the peer port shown by catalyst status, and allow node if macOS asks. There is no NAT traversal and no relay. The local API and dashboard listen on 127.0.0.1 only.

Trust

An invitation is a time-limited, single-use bearer secret. The peer link is TLS 1.2 PSK with forward secrecy. Every event is Ed25519-signed. Peer content reaches agents as quoted data, never as instructions.

Named agents, shared tasks and checkpoints

Tell Claude to plan work as Catalyst tasks and use subagents to work through the shared queue. Run catalyst for the connection, working agents, queue and conflicts.

  1. A worker takes a ready task. Catalyst saves its initial scope; the agent refines the plan with checkpoint_task before substantial edits.
  2. The worker records milestones, blockers, evidence, next steps and source branch/commit. Hooks remind it after five edited-file events.
  3. On a graceful stop, the saved checkpoint accompanies the released work. Another running eligible worker can take it and continue. Cross-device takeover still needs the source code through Git.

Detailed checkpoints sync through signed Catalyst events and remain in ignored .catalyst/ storage. They are excluded from the generated root IMPORTANT.md; ordinary public progress reports remain part of that handover.

Compatibility and limits

Protocol v2 cannot sync with v0.1 project data: set up fresh Catalyst projects and pair again. A disconnected peer keeps its existing task claims; queue workers continue on eligible local work. A hard kill cannot publish a final checkpoint or release. Catalyst does not restart failed Claude processes or wake idle sessions.

The integrated build is tested with two real local daemons. Interactive installation, conversational setup and physical two-laptop multiagent validation remain pending.

Uninstall

catalyst uninstall claude   # removes only Catalyst's entries from .mcp.json, .claude/settings.json, CLAUDE.md
catalyst stop
rm -rf .catalyst            # deletes this project's local event log, identity and keys. Cannot be undone.
npm unlink -g catalyst-coord

Catalyst shares context, not source files. Keep using Git to integrate code.
